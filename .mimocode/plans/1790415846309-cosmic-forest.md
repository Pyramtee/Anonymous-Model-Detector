# TokenizerDetector — 功能与架构计划（草稿）

## 0. 产品一句话

CLI 工具：对一个 OpenRouter 匿名模型发探针，利用其 **native tokenizer 的 usage 计数** 与本地已知 tokenizer 对齐，输出「可能是哪家的词表」Top-N + 置信度，并注明同词表模型列表。

---

## 1. 已确认的功能边界（Grill 结论）

| 维度 | 结论 |
|------|------|
| 检测能力 | 多信号融合 + 置信度，Top-N 候选，支持 unknown |
| API 目标 | 第一版只兼容 OpenRouter（OpenAI chat.completions） |
| 模态 | 仅文本 |
| 覆盖厂商 | Kimi/Moonshot、DeepSeek、智谱 GLM、小米 MiMo、StepFun、MiniMax、Qwen |
| 同词表策略 | 报到**厂商**，并注明该厂商哪些模型共用这套 tokenizer |
| 探针 | 内置固定探针集（可复现） |
| 已知库 | 直接依赖 `tokenizer.json`（HF 下载），不做指纹库 |
| 单次预算 | 5–15 次 API 调用 |
| 模板干扰 | 长探针 + 容差（不本地复现 chat template） |
| CLI | `fetch` / `detect` / `list` |
| 输出 | 终端摘要 + 可选 `-o report.json` |
| 栈 | Python + uv + HF `tokenizers` |
| 场景 | 个人研究、手动检测（不做队列/调度） |
| detect 输入 | 仅 OpenRouter `--model` id（base_url 固定官方，不做任意兼容端） |
| 探针策略 | 手工固定探针集（不做自动判别串挖掘） |
| 校准 | 不做 `calibrate` 子命令；验证时手动对已知模型跑 detect |

## 2. 关键事实（调研结论）

1. **OpenRouter usage 可信且对口**：官方文档写明 token count 用的是 **model's native tokenizer**，非流式在 `usage.prompt_tokens/completion_tokens`；流式在最后一条 SSE。这正是「匿名模型词表指纹」的理想信号。
2. **缓存陷阱**：OpenRouter 响应缓存命中时 usage 全部清零。探针必须防缓存（nonce / 唯一后缀 / 关闭缓存）。
3. **prompt_tokens 含 chat template**：发的是 `messages`，服务端会先套模板再 tokenize。模板差异约十几 token，用长探针把相对噪声压下去。
4. **国内词表可获得且跨代复用明显**：
   - Qwen2 / 2.5 / 3：词表 ~151643，基本未换
   - DeepSeek V3 / R1：共用 tokenizer（~129K）
   - Kimi K2：~160K
   - MiniMax-Text-01 / M1：~200064
   - GLM-4.5：~150K（tiktoken 风格 BPE）
   - MiMo-V2.5：HF 有独立 tokenizer.json
   - StepFun：实现时以 HF 官方仓库为准
5. **同 count 不同 vocab 会撞车**：因此必须有边界/判别探针，不能只比一个总数。

### 3.4 检测流水线（5–15 次调用）

1. **能力探测（1 次）**  
   极短请求，确认是否返回 `usage`；若无 usage → 明确报错/降级说明（第一版可直接失败并提示）。

2. **长判别探针（3–5 次，主信号 S1）**  
   内置 3–5 段长文本（中/英/代码/混合），每段带唯一 nonce 防缓存。  
   取 `prompt_tokens`，与各 family 本地 `tokenizer.encode` 长度比较：  
   `score = 1 - min(1, |n_api - n_local| / (n_local * tol + abs_tol))`  
   `tol` 吸收 chat template 差异（例如 2% + 8 tokens）。

3. **边界探针（3–4 次，强化区分同 count）**  
   短文本专打切分差异：emoji 组合、CJK 生僻字、罕见 Unicode、空格/换行边界、代码标识符。  
   即使 `prompt_tokens` 因模板噪声不可比，多条**相对模式**（哪条高哪条低）仍可当指纹。

4. **completion 复述（2–3 次，S2/S3，可选开启）**  
   要求模型逐字复述固定串；对复述文本本地 tokenize，比 count；并算 chars/token 等统计。  
   用于在 S1 区分度不足时加权。

5. **融合**  
   各 family 得分加权平均（默认 S1 0.55 / S2 0.25 / S3 0.20），softmax 归一化为置信度。  
   `unknown` 分数 = 1 - max(candidates) 的单调映射；若 top1 < 阈值（默认 0.55）或与 top2 过近 → verdict=`unknown` / `ambiguous`。

### 3.5 CLI

```bash
# 1) 拉取已知 tokenizer（只需一次）
tokenizer-detector fetch
tokenizer-detector fetch --family qwen,deepseek

# 2) 查看库
tokenizer-detector list

# 3) 检测匿名模型（仅 OpenRouter model id）
tokenizer-detector detect \
  --model "some/anonymous" \
  --api-key $OPENROUTER_API_KEY \
  [--max-calls 12] \
  [--no-completion] \
  [-o report.json]
```

环境变量：`OPENROUTER_API_KEY`（api-key 可省略）。base_url 内置为 `https://openrouter.ai/api/v1`，第一版不暴露自定义端点。

### 3.6 防坑清单（实现必须处理）

| 坑 | 对策 |
|----|------|
| OpenRouter 缓存 usage=0 | 每次探针加随机 nonce；检测到 total_tokens==0 则重试 |
| chat template 噪声 | 长探针 + 容差；不用短文本硬比绝对值 |
| 同词表撞车 | family 粒度上报 + shared_models 列表 |
| reasoning/cached tokens 干扰 | 只用 `prompt_tokens`/`completion_tokens` 主字段；忽略 details |
| 流式 | 第一版只用非流式，拿完整 usage |
| HF 下载失败 | `fetch` 可重试；`detect` 提示先 fetch |
| 词表真相同 vs 哈希巧合 | fetch 后对 tokenizer.json 做稳定哈希，相同哈希自动归并 family |

## 4. 实现计划（阶段）

### Phase A — 骨架与已知库
1. `uv init` + pyproject（deps: `httpx` 或 `openai`, `tokenizers`, `typer`, `pyyaml`, `rich`）
2. `data/vendors.yaml` 填 7 家的 HF repo 与 family
3. `fetch`：下载 tokenizer.json 到 `data/tokenizers/<family>/`，写哈希
4. `list`：打印 family / 厂商 / 共享模型 / 是否已下载

### Phase B — 探针与本地计数
5. `probes.py`：手工固定长判别探针 + 边界探针（版本化，写进测试）；不做自动挖掘
6. 本地 encode 统计表：每个 family 对每条探针的 token 数（可在 fetch 后生成缓存）

### Phase C — API 客户端与信号
7. `client.py`：非流式 chat.completions，解析 usage，nonce 防缓存，错误处理
8. 实现 S1/S2/S3 信号与 `fuse.py`

### Phase D — detect 与报告
9. 流水线编排（预算内选择探针组合）
10. 终端 rich 表 + `-o report.json`
11. 单元测试：fuse、容差、registry 归并；手动用 OpenRouter 已知模型做冒烟

### Phase E — 验证（人工）
12. 对 OpenRouter 上已知的 Qwen/DeepSeek/GLM 等跑 `detect`，看是否命中原 family
13. 对明显不在库中的模型（如 GPT/Claude）看是否倾向 unknown
14. 按结果调权重与阈值

---

## 5. 验证方式

- `uv run tokenizer-detector fetch && list` 库完整
- `pytest`：融合数学、容差、vendors 解析
- 手动：`detect --model qwen/qwen3-8b`（或任意在库模型）应高置信命中 Qwen
- 手动：匿名/不在库模型应倾向 unknown 或低置信
- 检查 `-o report.json` 结构完整

---

## 6. 明确不做（第一版）

- 图像/音频/多模态 tokenizer
- OpenCode 或其他非 OpenRouter 端点
- Web UI / 批量队列 / 定时监控
- 预计算指纹库（直接用 tokenizer.json）
- 本地复现 chat template
- 自动判别串挖掘
- `calibrate` 子命令
- 任意 OpenAI 兼容 base_url / OpenCode
- OpenAI / Anthropic / Gemini / Grok
- 从生成内容「猜」具体模型版本（只到厂商 family）
