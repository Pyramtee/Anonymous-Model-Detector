**TokenizerDetector 技术方案与阶段计划（待批准）**

版本：2026-09-26。范围：功能、识别算法、参考数据、实验协议、验收标准及后续工作顺序。本文件不启动架构设计或代码重构。

结论：项目可做成一个以原生输入 token 计数为主、特殊标记为定向补充、输出 token 字节为可选增强的匿名模型 tokenizer 检测工具。默认覆盖八家当前主系列，输出候选 tokenizer 家族及对应厂商线索。快检最多 12 次 HTTP 尝试；用户主动选择深检后累计最多 40 次。不能区分时保留候选集合，不能因为必须排名而输出确定厂商。

Step5 使用用户认可的固定镜像作为可信参考，来源信任问题已关闭。当前阶段不需要充值、API Key、新账号、GPU 或 OpenRouter 实测；全部验收采用本地 tokenizer、固定测试语料及模拟响应。线上匿名模型的真实识别结果，要在未来实际运行检测后才能得到。

**4. 检测结果究竟表达什么**

结果先回答“本轮哪些 tokenizer 能解释观测”，再映射到对应厂商。用户看到的主结论可以是“更符合腾讯 Hy4 tokenizer，厂商线索为腾讯”，但证据字段必须明确这是本次参考集和观测条件下的兼容判断。

同一 tokenizer 可以被不同模型使用；有限探针也不能证明完整词表相同。因此本工具不承诺识别模型权重、训练组织、参数规模或未公开新型号的确切名称。服务提供方 provider 与模型开发商分开记录。

| 结果状态 | 判定条件 | 报告用语示例 |
|---|---|---|
| `compatible` | 有效观测中只有一个 tokenizer 行为家族满足绝对匹配条件，且通过留出确认 | “与 Hy4 参考兼容；在本次候选集中唯一” |
| `ambiguous` | 两个或更多行为家族仍可解释有效观测 | “DeepSeek / Step 均兼容，特殊标记通道未能区分” |
| `no_reference_match` | 测量可用，但没有完整参考能在当前编码假设下解释观测 | “未匹配参考库；可能为库外 tokenizer 或未建模的服务端编码处理” |
| `insufficient_evidence` | 有效样本、确认样本或可用观测不足 | “预算耗尽，尚不能完成确认” |
| `unstable_endpoint` | 同一请求出现不能解释的计数变化，或混合路由无法拆开 | “测量不稳定，无法合并作归属判断” |
| `reference_unavailable` | 必需参考缺失、损坏或无法正确加载 | “参考库不完整，未生成八家唯一归属结论” |
| `request_failed` | 鉴权、额度、限流等问题使实验无法继续 | “请求失败，已保存完成部分” |

保留“未知”的产品含义，但不把一次拟合失败写成“发现了全新词表”。429、余额不足、超时、usage 缺失都不是成功拒识未知模型。

每份结论同时展示：候选集合、观测通道、绝对残差、区分第二候选的实际样本、未执行的理论可分探针、参考版本及停止原因。取消未经校准的百分比置信度；别名数量、候选排列顺序不能影响结论。

候选判定与停止原因分开记录。先检查参考完整性和测量有效性，再判断兼容集合，最后检查确认条件。缺少必要确认时，以 `insufficient_evidence` 为主状态并保留暂存候选，不能仅因剩下两家就称为完成了歧义判定。429 等后续错误不删除已有证据；如果此前已完成有效确认且没有新的矛盾，可保留已确认结果并附错误停止原因。若新观测显示漂移，则必须降级或按可比实验组展示，不能用旧结论掩盖新不稳定性。

**5. 各种识别方法的取舍**

| 方法 | 第一版定位 | 适用条件与判据 |
|---|---|---|
| 输入原生 token 计数 | 必做，主证据 | 实际文本的本地预测与远端计数能由稳定测量模型解释 |
| 成对差分 / 固定包裹 | 必做，消除稳定偏移并检验内容差异 | 不假设拼接可加；每次重新编码完整文本 |
| Unicode、空白、数字、代码边界 | 必做，作为有区分力的输入探针 | 以离线候选差异筛选，不能只按类别凑数 |
| 特殊 / added-token 标记 | 必做，针对普通词表共享组 | 双向标记、破坏语法的对照、普通文本策略兼容假设 |
| 原生输出 token bytes / logprobs 边界 | 可选增强 | 端点支持且返回可靠原生词元信息时启用 |
| 输出文本重编码与 completion_tokens | 诊断辅助 | 不作为严格相等的硬判据，不独立加权成第二份同源证据 |
| logit_bias 的 ID→字节实验 | 后续可选实验，不是第一版验收依赖 | 需要证明参数实际生效；阴性结果不能直接排除候选 |
| 模型自报 token 数、身份、文风与知识 | 不采用 | 不是 tokenizer 的直接观测 |

第一版已包含多种测量方式，但它们不必都是独立统计证据。输入差分、字符/token 比率和同一输出的计数转换不能重复投票。最终决策以证据约束是否相容为中心，不采用旧版 S1/S2/S3 固定权重相加。

**6. 输入计数的完整实验协议**

OpenRouter 文档说明 usage token counts 使用模型原生 tokenizer；据此将响应中的 prompt_tokens 作为首选观测，同时保存来源与原始字段。generation 诊断的 `native_tokens_prompt` 可能缺失；不能将缺失改成 0，也不能静默用语义不同的 `tokens_prompt` 替代。[Usage Accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting)、[Generation Metadata](https://openrouter.ai/docs/api/api-reference/generations/get-generation)

每个稳定实验组固定消息数量、角色、system 内容、工具配置、输出格式、推理设置和 provider 约束。第一版只发送文本单轮请求，不添加 tools、多模态载荷或无关插件。测量文本不能夹带每次变化的 nonce；若未来确实使用任何变化字段，必须纳入完整本地预测。

设第 i 次发送的完整用户文本为 x_i，服务返回的原生输入计数为 y_i，候选 tokenizer 为 k，预先定义的用户文本处理策略为 s。先使用以下测量假设：

`y_i = T_(k,s)(x_i) + b_g + ε_i`

`b_g` 是同一实验组 g 的未知外围开销，不要求很小。通过选择阶段样本的 `median(y_i - T_(k,s)(x_i))` 得到候选偏移，再在留出样本上验证。也可用同组锚点的差分检验相同约束；不把二者作为独立证据重复计分。

必须满足以下条件：

1. 本地编码的是实际发送的完整用户文本，包括固定前后缀、空白、换行和标记。
2. 同一组共用一个偏移；不能给每条探针各拟合一个偏移，也不能为救活候选任意增加分组。
3. 分组依据是请求配置与可见路由变化，不能依据“这样分组后某候选分更高”。每组样本不足时不能独立宣布匹配。
4. 在已经离线验证的包裹/编码测量模型下，默认严格模式以稳定整数计数和零残差为接受条件；不沿用旧版任意的 ±12 token / 2% 宽容差。模型适用性无法建立时，报告编码假设未验证或不适用，不能直接宣布目标一定来自库外。
5. 重复锚点出现变化时，先处理不稳定性，不能通过自动放宽阈值强行接纳。将来如增加噪声容忍模式，应作为独立、经过验证且明确降级的模式。
6. 固定包裹不能保证模板边界永远无影响。若普通固定偏移假设失效，只能检查事先定义并离线验证过的完整 chat 编码假设；不能随意拟合高阶函数消掉错误。
7. 即使重复锚点完全稳定，也仍需不同内容的留出确认，因为内容相关的服务端改写未必影响锚点。

每个家族维护全部仍合法的“tokenizer、用户文本策略、实验组偏移”组合，不能只留下一个分数最好的策略而丢掉其他可解释观测的组合。只有该家族的所有合法组合均失败，才能依据当前测量模型排除该家族。组合及实验组的种类预先定义，不能为拟合每条样本无限增加自由度。

候选从选择阶段进入确认阶段时，锁定整个存活假设集合及各自估计偏移。确认失败不得仍显示已确认；若重新选择探针或拟合，需要新的未使用确认样本与剩余预算。多个编码假设若都属于同一家族，可以给出家族兼容结论，同时保留编码策略尚未确定的说明。

DeepSeek V4.1 的官方 prompt 编码是独立实现，并非标准 Jinja 模板；参考资料必须保存相关编码规范，不能用“没有 chat_template.jinja”推断“没有模板”。第一版是否需要实现完整模板适配，由离线边界实验决定。[DeepSeek Prompt Encoding](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash#prompt-encoding)

**7. 特殊标记识别：重点解决 DeepSeek / Step5**

对剩余的 DeepSeek / Step 候选，停止追加不能提供新信息的普通长文本，切换到有方向性的标记。

选择阶段至少包含一条 Step 更短的标记和一条 DeepSeek 更短的标记。固定包裹下比较原始标记、破坏其语法的对照版本，并由各候选本地重新编码完整包裹。不能直接把上表裸串的 1/4 或 14/1 当成整个 API 请求的预测值。

随后用不同的标记或不同预先定义的边界上下文复核。第一条标记导致输出拒绝、工具样式文本或截断，并不能直接证明 tokenizer 身份；若输入 usage 完整且计数语义没有受破坏，该输入计数仍可独立评估。

对用户文字中的标记处理，保留两类有依据的假设：added-token 原子匹配；普通文本编码。每个假设必须适用于一组样本，不能逐条任意切换。官方后端有明确接口时使用接口；没有接口时，普通编码的本地模拟必须单独验证，不能仅删几个 JSON 字段便声称等同真实服务。

若目标在所有可用差异标记上都采用普通编码，则 Step / DeepSeek 的当前输入通道可能不可区分。正确结果是 `ambiguous`。这不是模型归属确认，也不是完整 tokenizer 文件相同；它意味着当前通道没有暴露可用差异。此时可尝试端点已经支持的输出 token 字节证据，若仍无差异则停止消耗请求。

**8. 输出侧增强与能力降级**

标准 OpenRouter chat logprobs 对象有 token、bytes、logprob 和 top_logprobs，不能假定它提供原生 token_id。数值 logprob 依赖模型权重与上下文，不作为纯 tokenizer 指纹。[官方 OpenAPI](https://openrouter.ai/openapi.json)、[参数文档](https://openrouter.ai/docs/api_reference/parameters)

若返回可靠的原生 token bytes，可检验某个输出词元的字节序列是否存在于候选词表中。不存在可以形成排除证据；存在只说明兼容。实现必须正确处理 token 的字节映射、byte fallback 与跨 UTF-8 边界，不能把 tokenizer.json 中的展示字符串直接当真实字节。输出记录的 bytes 缺失、不能还原相应可见输出或疑似经过替换时，该样本不用于硬排除。

输出 token 序列不要求等于“把最终输出重新 encode 一次”得到的规范序列。例如多个单字符 token 可以组成一个文本，而该文本规范编码只用一个 token。仅因为两种切分不同不能排除候选。

completion_tokens 可能包含隐藏 reasoning、结束符或其他不可见输出；隐藏 reasoning 文本也不等于关闭 reasoning。因此输出文本长度比、重编码计数与 completion_tokens 仅作诊断，不参与默认接受判定。输出为空但输入 usage 有效，不应自动丢弃输入实验。[Reasoning Tokens](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)

能力策略：输入计数是必需通道；logprobs、token bytes、reasoning 控制和 provider 固定都是可用时增强。能力分别记录为未探测、元数据宣称支持、实际观察到、明确不支持、返回不可靠。高级参数请求使用 `require_parameters=true` 并检查实际响应；参数不支持要记录并按预算降级，不能把被静默忽略的参数视为已启用。请求新参数若导致 provider 改变，则新实验单独分组。logit_bias 暂不放进默认 12/40 次流程，避免其支持性与采样结果引入新的不确定判断。

**9. 探针如何离线选择**

不使用昂贵模型生成探针。先构造固定、可审阅、可复现的文本池，覆盖中英文本、代码、数字分组、空白换行、组合附加符、常见与罕见 CJK、emoji/ZWJ、不同文字系统，以及参考库中的差异标记。

对每个候选及合法编码策略计算计数矩阵，再按剩余候选选择探针。普通阶段的区分力使用差分签名或消除共同偏移后的预测，不能只选裸计数方差最大的单条文本。

建议采用贪心的候选对覆盖：优先分开当前无法区分的候选对，再兼顾差异大小、请求文本长度与特殊处理风险。可使用预先界定的字符串拼接/变异来扩大差异，但每个组合必须重新 tokenize；重复 n 次的 token 数不能简单乘 n。

文本池预先分成选择池和确认池。确认池不能参与贪心选择、规则调参或阈值拟合；按事先冻结的类别与顺序调度，并检查是否达到预定的差异/覆盖条件。不能用两条所有候选都预测相同的文本满足“两条确认通过”：用于唯一判断的确认样本必须检验关键竞争关系或此前利用的编码差异；无信息的样本只能检查拟合稳定性。固定语料内容哈希、随机种子和 tokenizer 运行库版本，以便后来新增参考时重建矩阵并比较变化。

离线产物应包括：候选×探针计数矩阵、普通文本等价组、包含特殊标记的等价组、每个候选对的见证串、在不同端点能力下仍不可分的候选对。找不到见证串也应作为正式结果，不得为凑齐八家强行生成分类器。

**10. 快检与深检的预算和停止规则**

以下是资源预留建议，不是固定按顺序发送的脚本。可提前结束，且所有实际 HTTP 尝试都受统一预算约束。

| 快检预算用途 | 正常情况下的预留 |
|---|---:|
| 同一个锚点的基线与重复，兼顾基础能力发现 | 3 次 |
| 普通文本粗筛 | 3 次 |
| 自适应候选区分，包括标记与对照 | 最多 4 次 |
| 未参与选择的确认样本 | 至少预留 2 次 |
| 总上限 | 12 次 |

如果端点不支持参数、诊断请求或重试占用了预算，应减少探索并保留确认空间。不能在未完成确认时把“暂时唯一”升级成 `compatible`。只有 12 次不够时，输出当前候选和未完成事项，由用户决定是否继续深检。

深检上限为同一个实验累计 40 次，不是再增加 40 次。新增最多 28 次用于重新确认测量状态、更充分的边界与双向标记、可用的输出字节观测，以及最终确认；具体分配根据剩余候选决定，不把预算耗尽当目标。

继续深检时先检查模型 ID、参考版本、请求设置、可见 provider、记录完整性，并重复锚点检查会话间漂移。可比的数据复用；不可比的数据另分实验组并解释原因，不能为了复用而硬合并。重新运行本地分析、报告输出和回放不产生模型调用。

停止条件包括：通过确认且只剩一个行为家族；当前可用通道已无可分探针；测量不稳定；预算或输出限制已到；非重试型 API 错误；剩余请求不足以完成必要确认。每次停止都落盘部分证据。“已无可分探针”进一步区分经组件分析确定该通道等价、以及仅当前有限探针池没有找到见证；后者不能写成理论上永远不可区分。

预算在发送前扣减；超时、连接断开、429、5xx、参数错误、重试均占尝试次数。需要的 OpenRouter 元数据/诊断 HTTP 请求也计入本轮预算并单独标记类别。SDK/HTTP 隐式重试不得绕过计数；重定向应关闭或逐次计入；进程中断后已经扣减的尝试不能在续跑时重置。该上限约束本客户端发送次数，不等于 OpenRouter 内部上游尝试次数。参考文件准备单独记录为资料下载，不混入模型实验。默认不自动查询账户。

输入计数请求使用端点支持的较小输出上限，但不硬编码所有模型都接受 1 或 4 token。每种生成请求都必须设置有限输出上限；能力降级不得通过省略上限而回退为未知的服务端默认生成量。费用控制以请求数、最大输入/输出量和可取得的价格信息为依据；超时后服务端可能已经执行，不能宣称客户端能够保证绝对美元硬上限。

**11. OpenRouter 的路由、缓存和额度处理**

固定 model ID 不保证所有请求由同一个 provider 处理。支持时固定完整 endpoint slug，并关闭 fallback；仅指定 provider 基础名称可能仍覆盖多个区域/变体。保存实际返回的 model/provider/generation ID。无法固定或元数据不可见时，报告这一限制；稳定计数不能证明服务端从未变化。[Provider Routing](https://openrouter.ai/docs/guides/routing/provider-selection)

response cache 与 prompt cache 分开处理。response cache 默认关闭，可以请求 `X-OpenRouter-Cache: false`，不再靠随机 nonce 防缓存。response cache 导致零 usage 时不拿零值参与预测；prompt cache 的缓存读写字段则原样记录，不擅自从总 prompt_tokens 扣掉缓存 token。[Response Caching](https://openrouter.ai/docs/guides/features/response-caching)

额度不足、免费次数用完、429 限流属于运行条件问题。根据错误详情分类，区分账户余额不足与临时的 in-flight budget 限制；可重试时遵守 Retry-After、总预算及可配置时限。不无限重试、不替用户切换到付费模型、不自动充值。

免费额度规则只作背景资料：官方当前免费模型标称分档为每分钟 20 次；低购买量档每日 50 次，累计购买至少 10 credits 的高档每日 1,000 次。当前还存在提前 1 credit 进入高档的宽限及部分豁免，不能把“没余额”直接等同于某个免费档位。它不是当前工作的准备要求，也不改变用户明确的“不做 OpenRouter 测试”。[官方 Limits](https://openrouter.ai/docs/api_reference/limits)、[官方额度常量](https://github.com/OpenRouterTeam/docs/blob/main/snippets/exports/constants.mdx)

**12. 参考库和证据的可复现要求**

一个参考的身份至少由以下内容共同确定：仓库、固定 revision、文件清单与 SHA-256、加载后端及版本、基础词表映射、合并顺序/预分词正则、normalizer、added-token 配置、decoder、post-processor，以及用户文本编码策略。chat 编码规范单独保存。

文件哈希用于追溯；语义组件比较用于判断是否共享实现；有限探针矩阵用于判断某个观测通道下能否区分。三者不能相互替代。JSON merges 的字符串/数组序列化差异可以规范化比较，但不能排序合并规则而破坏其顺序。

不同模型可以映射到同一行为家族，文件不同也可能在当前通道不可分。别名只附加已知使用关系，不作为多个独立候选投票。失败时不静默从新参考回退到旧模型；损坏文件必须重新取得同一固定版本或明确报错。

Kimi 采用经过审查的本地适配方式复现官方逻辑；不在准备阶段任意执行浮动 revision 的 remote code。只下载 tokenizer 与必要配置/编码资料，不下载模型权重。

每次实验至少保存：实际请求文本和参数、脱敏响应与必要 headers、usage 全字段、输出及可用的 token bytes、错误与重试记录、时间、路由标识、参考 manifest、探针版本、软件版本、已花费预算、各候选预测/偏移/残差、每一步候选变化和停止原因。不保存 API Key 或 Authorization header。

回放必须能仅凭记录重算结果。报告中同时展示“本次已实测证据”与“参考文件理论上存在但本次未观察到的差异”，不把后者伪装成已完成验证。

默认选两份无需账号授权的官方非目标 tokenizer，只作为拒识对照，不加入中国厂商候选池。它们用于覆盖不同实现，不要求是对应厂商的最新旗舰：

| 对照 | 固定版本 | 本地四条 LONG 计数 |
|---|---|---|

| EleutherAI/gpt-neox-20b | [c292233c833e336628618a88a648727eb3dff0a7](https://huggingface.co/EleutherAI/gpt-neox-20b/tree/c292233c833e336628618a88a648727eb3dff0a7) | 666 / 352 / 338 / 393 |

对照不参与探针调优和接受阈值拟合。再做留一候选家族的实验：选探针与拟合时排除被留出的家族，再检查能否拒绝有可观察差异的留出对象。若被留出对象与仍在库内的对象具有相同可见行为，预期应为兼容/歧义，而不能要求算法凭空拒识。

| 验收项目 | 必须满足的标准 |
|---|---|
| 参考完整性 | 八家必需文件固定版本可加载；哈希与清单一致；缺失或损坏不静默跳过 |
| 官方行为对照 | Kimi 正则/特殊策略、HF 自动特殊 token 开关、字节与 Unicode 用例符合固定参考；不能只用同一个被测包装器生成真值 |
| 基础计数复现 | 复现第 3 节全部普通计数、差分签名和特殊标记计数 |
| 可分性 | 每个宣称可分的候选对有明确见证串；不可分组与证据通道一起报告 |
| 理想计数实验 | 在已声明的稳定模板/偏移/特殊策略模拟下，所有预期可分用例返回正确家族，不可分用例保留完整候选 |
| 留出确认 | 未完成确认不得接受；确认失败不得依靠重新拟合原确认样本变为已确认 |
| 共享词表与别名 | 增删同义别名或改变注册顺序不改变判定；DeepSeek/Step 普通编码策略下不硬分厂商 |
| 库外对照 | 两个独立外部对照及有可观察差异的留出对象不被错误接纳为某中国家族；报告用例数与失败详情 |
| 模板扰动 | 恒定偏移可处理；内容相关改写、错误边界模型不能通过无限扩张容差变成高置信匹配 |
| 路由不稳定 | 模拟 provider 切换、同请求不同计数、不可拆分混合时，按协议分组或停止 |
| 缓存与 usage | 缺失、零值、response cache、native 字段 null 等情况不产生伪匹配 |
| 输出侧 | 隐藏 reasoning、非规范生成分词、无 bytes、UTF-8 片段、空输出均不造成错误硬排除 |
| 请求预算 | 参数失败、429、超时、重试、metadata 请求及续跑合计均不超过设定次数 |
| 续跑与回放 | 可比样本复用；漂移不会被隐藏；回放无网络且与原始记录得到同一结果 |
| 报告 | 中文报告与 JSON 的候选、状态、预算和证据一致；不得出现虚构百分比置信度 |

这些是后续重构的验收门槛，当前尚未完成全部新方案验收。之前旧实现的 11 项测试通过不等于以上标准通过。

离线报告需要分别给出参考加载率、候选对可分覆盖率、条件模拟下的唯一接受率/歧义率/证据不足率、已接受结论的正确率、外部对照误接纳次数和平均实际尝试数。分母、模拟条件和样本数必须同时展示。有限对照通过不能推广为所有未知模型的拒识保证，更不能声称已取得线上准确率。验收运行时禁止真实网络请求，使用假凭证和模拟响应；公开参考文件应事先准备完成。
